How it works

From idea to in-game in three steps

Your work lives in a project folder. CDKit's runtime (cdkit.asi) builds your enabled mods when the game starts and loads them on top of the game's own data.

Create a project

Pick a folder and a name. Everything you change from now on is collected there – easy to back up, version and share.

Make your changes

Use the world editor, quest designer, item editor and assistants. Undo anything, preview it in 3D, test it with play mode.

Play and share

Start the game: the runtime builds your enabled mods behind a loading screen. Switch a mod off in the mod manager, or publish it as one package for other players.

Safe by design

Your game stays restorable

Mods stay separate from the game's own files. CDKit's small runtime (cdkit.asi, loaded by an ASI loader) builds your enabled mods when the game starts and shows them to the game while it runs – not a single original game file is changed. A mod switched off in the mod manager is gone at the next start, and several mods load together in your own order with every conflict listed.



Non-destructive

Mods load on top of the game. Switch them off in the mod manager and the next start uses the game's files.

Questions

Good to know

Is CDKit free?

Yes. Download it, unpack it and start CDkit.exe – no account, no installer.

Will it break my game or my save games?

No original game file is changed. The runtime cdkit.asi (loaded by an ASI loader in bin64) builds your enabled mods at game start, with a loading screen, and shows them to the game while it runs. “Disable this mod” or “Disable all mods” in the mod manager switches them off, and the next start uses the game's own files. Play mode blocks saving, so your saves stay safe while testing.

What do I need?

Windows 10 or 11 (64-bit), Crimson Desert on Steam, a DirectX 12 graphics card and the Microsoft Edge WebView2 Runtime (part of Windows 11 and every up-to-date Windows 10). To play mods, the game needs an ASI loader in its bin64 folder, for example Ultimate ASI Loader (not included). Play mode and live preview additionally use the World Builder plugin; importing MetaHuman/Fab packages needs Unreal Engine.

Do I need to know programming or 3D modelling?

No. Most tasks – moving objects, changing items, editing quests and texts – are done with forms and the mouse. For your own models you need a 3D file, the rest is handled by an assistant.

What happens when the game gets an update?

CDKit notices the new game version and shows which projects it affects. The runtime rebuilds your mods against the updated game at the next start – there is nothing to reinstall, and your changes carry over in almost all cases.

Can I share my mods?

Yes. “Publish mod” writes your mod as one .cdpkg package plus a ZIP for mod sites. Others add it with “Import mod”, drag their mods into their own load order, check conflicts, and can update a mod or undo an update.

Can players use my mods without CDKit?

Yes. They download CDKit Runtime (cdkit.asi and a mods folder) from the GitHub releases, unzip it into the game folder, add an ASI loader and put the .cdpkg files into bin64\CDKit\mods.

Where do I download CDKit?

There are two editions with the same editors: the standard edition from the GitHub releases, with built-in updates, and the Nexus edition on Nexus Mods, which opens no internet connection of its own and is updated through its Nexus page.

Where do I get help?

Start with the guide, and ask anything on our Discord.
